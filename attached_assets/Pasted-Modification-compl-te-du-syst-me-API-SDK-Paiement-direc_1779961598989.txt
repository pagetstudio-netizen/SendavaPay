Modification complète du système API SDK — Paiement direct sur le site du marchand

Modifier entièrement le fonctionnement actuel de l’API SDK.

Objectif :
Le client ne doit plus être redirigé vers une page SendavaPay.

Tous les paiements doivent désormais se faire directement sur le site ou l’application du marchand via API SDK.

---

Nouveau fonctionnement attendu

Ancien système (à supprimer)

Ancien flow :

1. Le marchand crée un paiement
2. SendavaPay génère paymentUrl
3. Le client est redirigé vers SendavaPay
4. Paiement effectué sur SendavaPay
5. Retour vers le site marchand

SUPPRIMER COMPLÈTEMENT :

- paymentUrl
- pages hosted checkout
- redirection SendavaPay
- page /pay/api/xxx

---

Nouveau système

Étape 1 — Création paiement API

Le marchand appelle :

POST /api/sdk/v1/create-payment

Réponse :

{
  "success": true,
  "data": {
    "reference": "sdk_abc123",
    "status": "pending",
    "paymentToken": "pay_tok_xxxxx",
    "expiresAt": "2026-05-28T12:00:00Z"
  }
}

IMPORTANT :

- Ne plus retourner paymentUrl
- Retourner uniquement :
  - paymentToken
  - reference
  - statut.

---

Étape 2 — Paiement directement sur le site marchand

Le marchand utilise le SDK SendavaPay pour afficher :

- opérateurs Mobile Money
- numéro téléphone
- OTP
- validation paiement

Tout cela directement sur SON site.

Exemple :

- Widget JavaScript
- SDK React
- SDK Flutter
- SDK Vue
- SDK HTML Embed.

---

Nouveau SDK JavaScript

Exemple :

<script src="https://sendavapay.com/sdk/sendavapay.js"></script>

---

Exemple d’intégration

SendavaPay.init({
  token: "pay_tok_xxxxx",
  amount: 5000,
  currency: "XOF",
  country: "TG",
  onSuccess: function(response) {
    console.log(response);
  },
  onFailed: function(error) {
    console.log(error);
  }
});

Le SDK doit afficher directement :

Sans quitter le site marchand.
